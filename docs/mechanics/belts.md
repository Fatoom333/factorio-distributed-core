# Механика транспортных лент Factorio 2.0 (для модели M0)

Цель документа: по нему можно написать потиково точную модель лент в ядре. Каждый факт помечен:

- **[П]** проверено по прототипам установленной игры (base 2.0.77, space-age) — читали файлы `data/*/prototypes/entity/*.lua`;
- **[И]** проверено по источнику (ссылка рядом), в игре не мерили;
- **[В]** вывод из проверенных фактов (логика, не измерение);
- **[Г]** гипотеза: в источниках нет, нужна сверка с игрой (см. «План сверки» в конце).

Единицы везде целые: позиция вдоль линии — в 1/256 тайла, время — в тиках.

## 1. Единицы и скорости

| лента | `speed` в прототипе [П] | за тик, 1/256 тайла | тайлов/с | предметов/с на полосу |
|---|---|---|---|---|
| transport-belt | 0.03125 | **8** | 1.875 | 7.5 |
| fast-transport-belt | 0.0625 | **16** | 3.75 | 15 |
| express-transport-belt | 0.09375 | **24** | 5.625 | 22.5 |
| turbo-transport-belt (space-age) | 0.125 | **32** | 7.5 | 30 |

- Скорость в прототипе — тайлов за тик; `speed * 256` — целое во всех четырёх случаях [П]. Подтверждено таблицей «Transport belts/Physics»: 8/16/24/32 позиций за тик [И] (https://wiki.factorio.com/Transport_belts/Physics).
- Шаг между предметами в плотном потоке — **64** (0.25 тайла), 4 предмета на тайл на полосу, у любой ленты [И, там же].
- Пропускная способность полосы = скорость / 64 * 60 предметов в с [И, там же]. Для express (24) шаг 64 не кратен скорости, поэтому периодических «тактов» нет — только целая арифметика позиций.
- Вывод для модели [В]: `v` (8/16/24/32) хранить в типе ленты, не в состоянии предметов. Float нигде не нужен.

## 2. Линия и полосы

- Тайл ленты имеет **две полосы** (lane), они независимы; у каждой постоянные плотность и скорость [И, Physics].
- Длина полосы прямого тайла — **256** позиций [И, Physics].
- Соседние ленты склеены в **одну транспортную линию**, у которой общий массив предметов; прямые и повороты уже сливаются, подземки встраиваются в длинную линию [И, FFF-176 https://factorio.com/blog/post/fff-176]. Lua API подтверждает: у `LuaTransportLine` есть `input_lines`/`output_lines`, а `line_equals` может быть истинно для разных тайлов, потому что линия охватывает несколько тайлов [И, https://lua-api.factorio.com/latest/classes/LuaTransportLine.html].
- Для M0 (только прямые стыки): полоса стыка из N тайлов подряд, направленных одинаково, — одна линия длиной **256·N** [В: из длины прямого тайла 256 и слияния]. Поворотов нет, значит и «внутренний/внешний» радиус (106 и 295 для поворота) не нужен [И, Physics, на будущее].
- Хранение в игре: не абсолютные координаты, а **расстояния между соседними предметами** плюс начальный и конечный зазор линии [И, FFF-176]. Для нашей модели можно хранить так же (`Vec<u32>` зазоров) или абсолютные позиции — результат один; зазоры удобнее, потому что при свободном потоке меняется только пара чисел.
- Какой конец линии «ноль» в API: **не документировано** [И: доки LuaTransportLine прямо об этом молчат]. Для модели это только вопрос договорённости о системе координат; но для сверки с `insert_at(position, ...)` и `get_detailed_contents` нужно выяснить [Г] — см. план сверки.

Предложение для модели [В, договорённость]: позиция предмета `p` отсчитывается от начала линии (хвоста, откуда лента принимает) к концу (голове); `p` = центр предмета, `0 <= p <= L`, `L = 256·N`.

## 3. Порядок обновления за тик

Из FFF-176 [И]: при свободном потоке линия двигает «только концевые зазоры», а при подпоре — последний ненулевой зазор; «если лента сжалась, она остаётся такой навсегда» (индекс последнего положительного зазора кэшируется и сдвигается только назад). Отсюда эквивалентный алгоритм:

```
для каждой полосы линии, предметы по порядку ОТ ГОЛОВЫ К ХВОСТУ (i = 0 — самый передний):
    лимит(0)  = L                          // [Г] см. §4: может быть L, а не L - что-то
    лимит(i)  = новая_позиция(i-1) - 64    // для i > 0
    новая_позиция(i) = min(p_i + v, лимит(i))
```

- Важно: лимит берётся от **новой** позиции переднего предмета, а не старой [В]. Иначе в свободном потоке каждый следующий предмет отставал бы на тик, и плотная полоса не ехала бы целиком со скоростью `v`; а по FFF-176 она едет, меняя только два числа. Если передний предмет упёрся, лимит от старой и новой совпадает — результат тот же.
- Движение не сближает предметы меньше чем на 64 [В]; вставку в зазор меньше 64 см. §5.
- Движение полос независимо [И], порядок между полосами и между линиями на результат не влияет, пока нет взаимодействий (манипуляторы, стыки). Стык двух линий (конец одной → начало другой), если они не склеены в одну, — не нужен: склейка делает стык внутренним.
- Сжатие: после того как предмет догнал соседа до зазора ровно 64, он двигается в том же такте, что сосед [В]. Зазоры не расширяются сами, только вставкой и забором [В из FFF «навсегда»].

Фазовый нюанс [Г]: порядок «сначала двигаем линию, потом работают манипуляторы» или наоборот внутри одного тика меняет результат сверки на 1 тик. Нужен замер: в тик T манипулятор видит предмет на позиции до или после движения лент этого тика. Принять в модели порядок, который покажет сверка.

## 4. Конец линии: где останавливается предмет

Документированных данных **нет** [И: wiki Physics и Lua API молчат]. Известно только:

- Каждый предмет логически находится ровно на одном тайле; если тайл остановлен — предмет стоит, иначе едет, «промежуточных состояний нет» [И, Physics, «Tick example»].
- Для остановленных тайлов wiki пишет, что «самые передние остановившиеся предметы выступают на разную величину» [И, Physics] — то есть у остановленного предмета видимый вылет за край тайла зависит от фазы; расчётная позиция остановки в виде одного числа всё же должна существовать.
- Ёмкость прямого тайла в подпоре — 4 предмета на полосу [И: https://forums.factorio.com/viewtopic.php?p=424201, данные 2019 года, могут устареть].

Гипотеза [Г]: голова упирается в конец линии на `p_0 = L - c`, где `c` — константа порядка 0..32 (половина размера предмета?). Из 4 предметов на 256 при шаге 64 следует: если `c = 32`, головы выстраиваются на 224, 160, 96, 32 (и 4-й влезает) — это согласуется с ёмкостью 4. Если `c = 0`, позиции 256, 192, 128, 64, 0 — пятый предмет влез бы на `p = 0` (центр на самом входе), т.е. ёмкость 5. Данные про ёмкость 4 в подпоре поддерживают `c` > 0, но точную `c` надо измерить.

## 5. Манипулятор и лента (со стороны ленты)

Параметры обычного (жёлтого) манипулятора [П, base 2.0.77, `entities.lua`]:

- `pickup_position = {0, -1}`, `insert_position = {0, 1.2}` (у `fast-inserter` те же) — то есть захват с центра соседнего тайла «сзади», выгрузка на 1.2 тайла «спереди» (0.2 тайла за центр соседнего тайла в сторону от манипулятора).
- `rotation_speed = 0.014` оборота за тик, полный оборот 70 тиков [П + И: https://wiki.factorio.com/Inserters]; `extension_speed = 0.035` [П]. Подробности цикла — в документе манипуляторов.

**Куда кладёт.**

- Полоса: «дальняя от манипулятора» [И: https://wiki.factorio.com/Inserters]. Для ленты вдоль оси манипулятора (в его сторону или от него) — **правая полоса по движению ленты** [И: форум https://forums.factorio.com/viewtopic.php?p=434677 и др. ветки «Is Inserter item drop position intuitive?» — наблюдения игроков, не официально]. Для перпендикулярной ленты — полоса, дальняя от манипулятора.
- Позиция вдоль полосы: физическая точка падения определяется положением руки (`insert_position`), но окончательное решение по полосе принимает отдельный шаг выбора [И-слабое: тот же форум, мнение одного участника]. Точная формула «позиция тайла → `p`» — **[Г]**; в M0 принимаем: `p` = (начало тайла в линии) + проекция точки падения на ось ленты, переведённая в 1/256, и сверяем.
- Условие вставки: на полосу нельзя класть, если она сжата без зазора; манипулятор ждёт. Если зазор меньше предмета, предметы выше по потоку **притормаживают**, освобождая место [И, Physics: «Entities that add items … enlarge a small gap until it fits the item exactly. Belts therefore compress before items back up»]. Это значит: вставка в зазор ≥ 64 допустима всегда; в зазор < 64 — только через «расширение» зазора (сдвиг хвоста назад) — механика не описана [Г].
- Lua `insert_at(position, items, belt_stack_size)` возвращает `false`, если места нет; условия не описаны [И, Lua API]. `force_insert_at` вставляет, «возможно, сминая» предметы [И]. Замеры `insert_at` в проекте: 0.71 мкс/вставка (`bench/RESULTS.md`).

**Откуда берёт.**

- Манипулятор берёт только предметы, которые логически на тайле перед ним, а не те, что «торчат» из соседних тайлов [И, Physics].
- Выбор полосы: с перпендикулярной ленты — ближняя полоса, если пуста — дальняя; с ленты, идущей на манипулятор, и с поворота — левая по движению, если пуста — правая [И, Inserters].
- Не берёт то, что принимающая сущность не примет [И]; сложнее брать с быстрых лент, с входов/выходов подземок и с внутренней стороны поворота [И]. Точное «окно захвата» в позициях (какие `p` относятся к тайлу) — **[Г]**: по логике «ровно на одном тайле» — `p` в `[256·k, 256·(k+1))` для k-го тайла линии, но граница (включая ли край) не подтверждена.
- Захватывается ближайший к голове подходящий предмет в окне [Г].

## 7. План сверки (какие замеры закрывают [Г])

1. Тупик: прямая лента из N тайлов без продолжения, залить предметами до стопора; через `get_detailed_contents` / `get_item_position` считать позиции всех предметов → найти `c`, направление отсчёта, ёмкость.
2. Одна `insert_at` в пустую линию на известную позицию, чтение позиции назад → единицы и начало отсчёта.
3. Манипулятор из сундука на пустую ленту (обычную, быструю): по тикам снимать позицию предмета сразу после падения → позиция падения и порядок «лента/манипулятор»; повторить для лент, идущих от манипулятора, к нему и перпендикулярно.
4. Плотная лента с зазором меньше 64 перед манипулятором → поведение притормаживания.
5. Сверка модели и игры после каждого тика на 1000+ тиков для сцены «сундук → манипулятор → лента → манипулятор → сундук».
