# Замер RCON

Отвечает на вопрос: потянет ли RCON поток изменений мира тик в тик.

## Как запустить

```powershell
# 1. Отдельное окружение Factorio (свои сейвы/моды не трогает) — один раз
.\bench\setup-env.ps1
# 2. Сервер без окна, RCON на 127.0.0.1:27015 (или клиент с окном: .\bench\run-client.ps1, затем хост из меню)
.\bench\run-server.ps1
# 3. В другом окне — замер
# пароль и script-output берутся из ..\bench-env (другое место — $env:FD_ENV_DIR)
cargo run --release --bin rcon_bench -- all   # или transport / events / freeze / insert
```

Окружение создаётся в `../bench-env` (рядом с репозиториями, не в git): свой `config.ini`,
карта, ссылка на мод `../factorio-distributed-mod`, случайный пароль RCON.
Сервер слушает только `127.0.0.1`, не виден ни в публичном списке, ни в LAN,
не встаёт на паузу без игроков (`auto_pause = false`).

**Только для однопользовательской машины.** `run-server.ps1` передаёт пароль RCON флагом
`--rcon-password`, поэтому пароль виден любому локальному процессу, читающему список
процессов (работает ли для `--start-server` пароль из `config.ini`, как у `run-client.ps1`,
не проверено).
Не запускайте этот сервер на общей машине. `-Factorio` — путь к исполняемому файлу игры, если игра
стоит не в папке Steam по умолчанию.

Съёмка эталонов модели (M0) — `scene_capture`, см. [tests/fidelity/README.md](../tests/fidelity/README.md).

Все команды — `/fd <JSON>` (своя команда мода): она не отключает достижения и не
выполняет произвольный Lua. Результаты — [RESULTS.md](RESULTS.md).

## Фаззер M0 (случайные сцены пачками)

Отдельное окружение, чтобы не мешать другим прогонам (свои порты, свой каталог данных):

```powershell
.\bench\setup-env.ps1 -EnvDir ..\bench-env-fuzz        # один раз; в mods\ добавить ссылку на bench\test-mods\fd-test-vectors
.\bench\run-server.ps1 -EnvDir ..\bench-env-fuzz -RconPort 27016 -Port 34198
```

`bench/test-mods/fd-test-vectors` — тестовый мод, разрешающий менять векторы манипулятора
(`allow_custom_vectors`); пользователям он не нужен. Дальше (адрес и каталог окружения — из переменных):

```powershell
$env:FD_RCON_ADDR = "127.0.0.1:27016"; $env:FD_ENV_DIR = "..\bench-env-fuzz"; $env:FD_RUNS_DIR = "..\fuzz-runs"
cargo run --release --bin fuzz_capture -- --seed 1 --count 1000 --batch 100   # сцены -> fuzz-runs\1\
cargo run --release --bin fuzz_report  -- --run ..\fuzz-runs\1                 # сравнение модели с игрой; при панике модели — код выхода 1
cargo run --release --bin fuzz_gen     -- --seed 1 --count 10 --out scenes     # только сгенерировать
```

Мод: сцены строятся `scene_build_many`, стартуют вместе `scene_run_all` (`"ext": true` добавляет
в дамп манипулятора фактические `pickup`/`drop`); съёмщик забирает дампы и сносит сцены `scene_clear`.
`fuzz_report` строит модель (`World::from_scene`), гонит её тик в тик и сводит первые расхождения по видам.
Генератор по умолчанию не порождает сцены с известными расхождениями модели: несколько стоков на ленте
(`--compete`), сток на конце ленты и очередь до стока (`--compress`), несколько видов предметов в сундуке
(`--multi-item`); `--known-bad` включает все три. `--all-inserters` добавляет быстрый и длиннорукий
манипуляторы (модель знает их с 09.10; по умолчанию выключено, чтобы старые прогоны оставались
сравнимыми).

Сцена по номеру детерминирована (`seed`, `idx`); `--turns` включает повороты и боковую загрузку
(M0.5), `--no-vectors` отключает кастомные векторы. Операции мода — `scene_build_many` и `scene_run_all` (см. `scene.lua`).

Сцена воспроизводится по имени: `s<seed>-<номер>` (например `s101-00774`) — это `fuzz_gen --seed 101`
(с теми же флагами, что при съёмке), сцена с индексом 774. Папки прогонов (`fuzz-runs/<seed>` и т. п.)
лежат вне git; в документах на них ссылаются как «фаззер, seed N».

## Отладочные примеры (`examples/`)

Запуск: `cargo run --release --example <имя> -- <аргументы>`; аргументы — в шапке каждого файла.

- `first_mismatch` — первое расхождение модели и игры в каждой сцене папки прогона.
- `model_dump` — прогнать сцену в модели и напечатать состояние каждого тика (формат эталона).
- `trace` — потиковый след одного манипулятора: модель против эталона.
- `belt_line_diff` — потиковый след полос одной линии лент: модель против эталона.
- `hand_obs` — выгрузка наблюдений руки (состояние модели и `hand` эталона) по папке прогона.
- `overcompressed_scan` — события «вставка, после которой задний предмет ближе 64» и что было дальше.

`bench/tail-probes/gen.py` — генератор проб «кладка за хвост линии» (сцены для `fuzz_capture --scenes`).
